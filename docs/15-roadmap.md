## 15.2 決定事項

本仕様で決めた設計上の判断と、その理由を記録する。

| ID | 決定 | 理由 |
|---|---|---|
| D-01 | Node.js 24 以上を対象とし、ESM のみで配布する。コアは環境非依存に保つ | 主な用途（CLI、サーバー、ビルド）を優先しつつ、将来のブラウザ対応を妨げないため。Node.js 22 は v1.0 の時期までにサポートが終わる見込みのため対象外とする |
| D-02 | 内部の単位を mm とし、組み込みの既定値は仕上がり幅に比例させる | 印刷が主な用途であり、判型を変えても見た目の比率を保つため |
| D-03 | 文字は HarfBuzz でシェーピングし、字形の輪郭として描く | 縦書きを正確に組むため、プラットフォーム間で出力を一致させるため、文字を手描き風に変形するため |
| D-04 | 表示リストは塗りだけで構成し、線の命令を持たない | 太さの変化する手描きの線を表すため、バックエンド間で見た目を一致させるため |
| D-05 | 和文フォントを同梱せず、推奨フォントは別パッケージで提供する | パッケージのサイズとライセンスのため |
| D-06 | 手描き化の既定を `ink` とし、写植の文字は揺らがせない | 商業漫画の見た目（手描きの線と写植の文字）に合わせるため |
| D-07 | 右綴じ、右から左の読み順、縦書き、天揃えを既定とする | 日本の漫画の慣習に合わせるため |
| D-08 | 吹き出しの既定のクリップを `none` とし、枠線の上に描く | 吹き出しがコマの枠にかかる表現は一般的であるため |
| D-09 | ネットワークアクセスとルート外のファイル参照を既定で禁止する | サーバーに組み込んだ場合の安全性のため |
| D-10 | ID をドキュメント全体で一意とし、シードを ID から導出する | 要素の局所的な変更が他の要素の線を変えないようにするため |
| D-11 | ルビ・傍点は Web 小説で一般的な記法（`｜親文字《ルビ》`、`《《傍点》》`）、その他はタグで書く | 日本語の書き手が慣れた記法であり、YAML の構文と衝突しにくいため |
| D-12 | 2 値出力では、連続階調を要素ごとに網点化してから合成し、最後に 2 値化する | 線の縁の中間調が網点化されて汚れるのを防ぐため |
| D-13 | 組み込みの形状・効果もプラグインの仕組みで実装する | 拡張の仕組みを常に検証された状態に保つため |
| D-14 | 角度は 0 度を右向き・時計回りとする。ただしグラデーションの角度だけは CSS と同じ規約（0 度が上向き）とする | 座標系（y 軸が下向き）と一貫させるため。グラデーションは CSS の書き方をそのまま使えるようにするため（人や AI が CSS の知識で書くと 90 度ずれる事故を防ぐ） |
| D-15 | 主な記述形式を YAML とし、JSON と TypeScript オブジェクトも同じスキーマで受け付ける | YAML は手で書きやすく、コメントと複数行のセリフを書ける。プログラムからの生成には JSON・オブジェクトが向くため |
| D-16 | 見た目・レイアウト・既定値の変更をトップレベルの `engine` の番号で管理する | ライブラリの更新で既存のドキュメントの出力が変わらないようにするため |
| D-17 | 重なった吹き出しは、先に読む吹き出しを手前に描く | 重なった吹き出しは手前のものから読むという慣習に合わせるため |
| D-18 | 禁則の既定を `strict`（小書きの仮名・長音記号も行頭禁止）とし、強さの区分は CSS Text 3 の `line-break` に合わせる | 漫画の写植の慣習に合わせ、かつ区分を既存の規格で定義するため |
| D-19 | 色・グレーから網点への変換は、既定で線形の輝度を使う | 網点化した結果を離れて見たときの明るさを元の色と一致させるため |
| D-20 | 自動 ID とシードはレイアウトの結果に依存させず、リストの順番だけから決める | 処理の段階の依存関係を単純にし、レイアウトの変更で線が描き直されないようにするため |
| D-21 | パッケージ名・コマンド名・スキーマの識別子を `mangacli` とする | 決定済み（2026-11-03 時点で npm の名前は未使用） |
| D-22 | ライセンスを MIT とする | 決定済み |
| D-23 | 和文フォントは同梱せず、OFL のフォントのカタログと取得の仕組みを同梱する。セットアップ時（`fonts install`・`init`）またはレンダリング時に、版とハッシュを固定してダウンロードする。npm の `postinstall` は使わない | パッケージを小さく保ちつつ、フォントを用意しなくてもすぐにレンダリングできるようにするため。インストール時のネットワークアクセスを避けるため（[7.3.10](07-text.md#7310-フォントのカタログと取得)） |
| D-24 | 数値の既定値（寸法、手描きのパラメータ、揃え、網点化の変換など）は暫定値とし、M1 の実装中にサンプルを作りながら調整する。確定した値を `engine: 1` として固定する | 実際の出力を見ながら決めるのが確実なため |

## 15.4 リスク

| ID | リスク | 対策 |
|---|---|---|
| R-01 | 手描きらしさの評価が主観的で、既定値が定まらない | 機械的な基準（14.4.1）と目視の評価（14.4.2）を組み合わせ、評価の記録を残す |
| R-02 | WebAssembly 版の HarfBuzz の性能・サイズ | M0 で計測する。シェーピング結果をキャッシュする |
| R-03 | ネイティブ依存（Skia 系、libvips 系）の導入が一部の環境で失敗する | プリビルドバイナリのある依存に限定し、CI で全 OS を検証する |
| R-04 | 600 dpi の出力のメモリ使用量 | 並列数の自動調整、素材の縮小デコード、ページ単位の解放 |
| R-05 | フォントのライセンスの誤解 | カタログを OFL のフォントに限り、取得時にライセンス文を保存する。`fonts licenses` とドキュメントで再配布時の注意を示す |
| R-06 | ICU の違いで文節の区切りが変わり、出力が環境に依存する | 手動の改行を推奨し、区切りの関数を差し替えられるようにする |
| R-07 | 仕様の範囲が広く、v1.0 までの期間が長くなる | P0 / P1 / P2 で段階的に出し、M1 の時点で実用できる状態にする |
| R-08 | カタログのフォントの取得元のファイルが消える・変わる | 版を固定した URL とハッシュの検証、`fontMirror`、CI での定期的な照合（[14.1](14-quality.md#141-テストの方針)）。取得元を変える場合はカタログの項目を更新する |

## 15.5 実装の状況（engine 1）
