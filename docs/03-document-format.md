# 3. ドキュメント形式

## 3.1 概要

ドキュメントは、1 冊（または 1 話）の漫画の構造を表す。YAML ファイルで書くことも、TypeScript オブジェクトとして API に渡すこともできる。両者のスキーマは同一である。JSON ファイル（`.json`）も、YAML と同じスキーマとして受け付ける。

主な記述形式を YAML とするのは、人が手で書きやすく（引用符や括弧が少ない）、コメントを書け、複数行のセリフをそのまま書けるためである（[15.2](15-roadmap.md#152-決定事項) の D-15）。

### 3.1.1 最小の例

```yaml
mangacli: 1

assets:
  taro: ./assets/taro.png

pages:
  - layout:
      rows: [[1], [1, 1]]
    panels:
      - layers:
          - image: taro
          - balloon: おはよう
      - layers:
          - balloon: |
              今日は
              いい天気だね
      - layers:
          - effect: focus-lines
          - text: その時——
            place: top-right
```

この例は、B5 判・モノクロ・右綴じ・縦書き・手描き風（`ink` プリセット）の既定値で、1 段目に 1 コマ、2 段目に 2 コマ（右が 2 コマ目）のページを 1 枚出力する。フォントを登録していないため、既定のフォントセット `manga-basic`（アンチゴチ・明朝体など）を使い、手元になければ初回のレンダリング時にダウンロードする（[7.3.10](07-text.md#7310-フォントのカタログと取得)）。使う機能はすべて P0 である。


### 3.1.2 プロジェクトの構成

推奨するディレクトリ構成を示す。構成は強制しない。

```text
my-manga/
├── mangacli.config.ts     # 設定ファイル（任意、12.5）
├── manga.yaml             # エントリのドキュメント
├── shared/
│   ├── characters.yaml    # インポートする共有定義
│   └── styles.yaml
├── chapters/
│   ├── ch01.yaml          # インクルードするページ群
│   └── ch02.yaml
├── assets/                # 素材画像
├── fonts/                 # フォントファイル
└── out/                   # 出力先
```

- プロジェクトルートは、既定でエントリの YAML があるディレクトリとする。設定ファイルで変更できる。
- ドキュメント内の相対パスは、**そのパスが書かれたファイル**のディレクトリを基準に解決する。
- API にオブジェクトまたは YAML 文字列で渡した場合は、`baseDir`、なければ `root`、なければ作業ディレクトリを基準とする（[11.2](11-api.md#112-主要な関数)）。

## 3.2 YAML の扱い

1. YAML 1.2（Core Schema）として解析する。文字コードは UTF-8 とし、BOM があれば無視する。
2. アンカー（`&`）とエイリアス（`*`）を使える。マージキー（`<<`）は YAML 1.2 の Core Schema には含まれない（YAML 1.1 の型）が、利便性のため、Core Schema のまま `<<` だけを追加で解釈する（`yaml` ライブラリでは `{ version: "1.2", schema: "core", merge: true, uniqueKeys: true }` に相当）。展開数の上限は [2.13](02-architecture.md#213-セキュリティ) に従う。
3. カスタムタグは使えない。
4. 重複したキーはエラーとする（`YAML_DUPLICATE_KEY`）。
5. マップのキーの順序は意味を持たない。リストの順序は意味を持つ（コマの割り当て順、要素の重なり順など）。
6. YAML 1.1 の真偽値（`yes`、`no`、`on`、`off`）は文字列として扱う。真偽値は `true` / `false` のみである。
7. 文字列の改行コードは LF に統一する。ID、名前（素材・フォント・スタイル・キャラクターなど）、キーワードは Unicode 正規化形式 C（NFC）に正規化して比較する。本文は NFC に正規化しない（CJK 互換漢字が統合漢字に置き換わり、人名などの字形が変わるのを防ぐため）。
8. 本文のキー（`text`、`placeholder`、`title`、`name` など文字列型のキーと、本文の短縮形 `balloon`、`sfx`）に書いたスカラーは、YAML の型の解決を行わず、書かれた表記のまま文字列として読む。`100`、`0123`、`1e3`、`true`、`~`、`null`、`.inf` なども文字列になる（先頭の 0 も失われない）。引用符とブロックスカラーの処理は通常どおり行う。
9. 本文に折り畳みブロックスカラー（`>`）を使うと、改行が半角空白に置き換わり、縦書きでは不要な空きになる。この場合は警告（`TEXT_FOLDED_SCALAR`）を出す。
10. 変数、条件分岐、繰り返しなどのテンプレート機能は提供しない。共通の値はアンカー・エイリアスとスタイル（[3.16](#316-styles)）で、繰り返しの生成はプログラム（[11](11-api.md)）で行う。

### 3.2.1 セリフを書くときの注意

YAML では、値の先頭に特定の記号があると、文字列ではなく構文として解釈される。セリフでは次の点に注意する。

| 先頭の文字・含まれる文字 | 問題 | 対処 |
|---|---|---|
| `!` | タグとして解釈される（例: `!?` で始まるセリフ） | 引用符で囲む、またはブロックスカラーを使う |
| `#`（直前が空白） | コメントとして解釈される | 引用符で囲む |
| `:`（直後が空白） | マップとして解釈される | 全角の `：` を使う、または引用符で囲む |
| `[`、`{` | リスト・マップとして解釈される | 引用符で囲む |
| `\|`、`>` | ブロックスカラーとして解釈される | 引用符で囲む |
| `*`、`&` | エイリアス・アンカーとして解釈される | 引用符で囲む |
| `-`、`?`（直後が空白） | リスト・複合キーとして解釈される | 引用符で囲む |
| `%`、`@`、`` ` `` | 予約された記号（エラーになる） | 引用符で囲む |
| `'`、`"` | 引用符の始まりとして解釈される | 反対の種類の引用符で囲む、またはブロックスカラーを使う |
| `{page:03}` のような波括弧で始まる値（ファイル名のテンプレートなど） | マップとして解釈される | 引用符で囲む |

- ダブルクォートの文字列の中では、YAML のエスケープ（`\n` など）が先に処理される。インラインマークアップのエスケープ（`\《` など、[7.7](07-text.md#77-インラインマークアップ)）をダブルクォートの中で書く場合は `\\《` とする。シングルクォートとブロックスカラーの中では `\《` のまま書ける。

**推奨**: 複数行のセリフ、および記号で始まるセリフは、リテラルブロックスカラー（`|`）で書く。ブロックスカラーの中では改行がそのまま行（縦書きでは列）の区切りになり、記号のエスケープも不要である。

```yaml
- balloon: |
    !?
    なんで
    ここに……
```

ブロックスカラーの末尾の改行は無視する（`|-` と同じ扱い）。

## 3.4 値の型

### 3.4.1 長さ（Length）

数値、または数値と単位の組の文字列で表す。

```yaml
width: 0.3mm
padding: 1.2em
fontSize: 13Q
x: 40        # 単位なしは page.units（既定 mm）
```

- 文字列の形式は `<数値><単位>`。数値と単位の間に空白を入れてもよい。
- 負の値は、意味がある場合（`offset` など）のみ許可する。

### 3.4.2 割合（Percent）

`"<数値>%"`。何に対する割合かは、使う場所ごとに定める。座標とサイズでは、基準となる領域（[3.6](#36-座標系)）の幅または高さに対する割合である。

### 3.4.3 角度（Angle）

数値（度）、または `"<数値>deg"`、`"<数値>rad"`、`"<数値>turn"`。0 度は右（+x 方向）、正の値は**時計回り**（y 軸が下向きのため）。

ただし、グラデーション（`linear-gradient()`、`tone-gradient()`、塗りの `gradient.angle`、ハッチングの `gradient.angle`）の角度だけは、CSS と同じく **0 度が上向き（下から上へ進む）、90 度が右向き**の時計回りとする（[8.14.1](08-effects.md#8141-グラデーション)）。CSS の書き方をそのまま使えるようにするためである。

### 3.4.4 点（Point）

次のいずれか。

| 形式 | 例 | 意味 |
|---|---|---|
| 座標 | `[30%, 20mm]` | 基準領域内の座標 |
| 位置キーワード | `top-right` | 基準領域の 9 点（`top-left`、`top`、`top-right`、`left`、`center`、`right`、`bottom-left`、`bottom`、`bottom-right`） |
| 参照 | `taro1`、`taro1.mouth`、`taro1.top-left` | 要素・素材のアンカー・外接矩形の点（[3.7](#37-id-と参照)） |

### 3.4.5 サイズ（Size）

`[幅, 高さ]`。各値は長さ・割合・`auto`。`auto` は要素の種類ごとに定める（画像では縦横比の維持、吹き出しでは本文に合わせる）。

### 3.4.6 矩形（Rect）

`[x, y, 幅, 高さ]`。

### 3.4.7 範囲（Range）

不規則にばらつかせる値。`[最小, 最大]` の 2 要素のリストで表し、要素ごと・線ごとに一様分布で値を選ぶ。単一の値を書いた場合はばらつかない。

```yaml
thickness: [0.15mm, 0.6mm]
```

分布を指定する場合はオブジェクトで書く: `{ min: 0.15mm, max: 0.6mm, dist: normal }`。`dist` は `uniform`（既定）、`normal`（平均は中央、±2σ が範囲。範囲外の値は範囲の端に丸める）、`low`（小さい値に偏る）、`high`（大きい値に偏る）。分布ごとの変換式は [9.2.1](09-hand-drawn.md#921-擬似乱数生成器) に従う。

### 3.4.8 色（Color）

CSS Color Level 4 の次の形式に対応する。

- 色名（`black`、`white`、`red` など CSS の名前付き色）
- `#rgb`、`#rgba`、`#rrggbb`、`#rrggbbaa`
- `rgb()` / `rgba()`、`hsl()` / `hsla()`
- `transparent`

本ライブラリ固有の別名として、`ink`（`#000000`）と `paper`（`#ffffff`）を使える。色空間は sRGB とする。

### 3.4.9 塗り（Paint）

| 形式 | 例 | 意味 |
|---|---|---|
| 色 | `white` | 単色 |
| `none` | `none` | 塗らない |
| トーン | `tone(30%)`、`tone(20%, 65lpi, 45deg)`、`tone(15%, noise)` | スクリーントーン（[8.13](08-effects.md#813-トーン)） |
| トーングラデーション | `tone-gradient(0%, 40%, 90deg)` | 濃度が変化するトーン |
| グラデーション | `linear-gradient(180deg, #fde 0%, #fff 100%)`、`radial-gradient(...)` | CSS の構文のサブセット（[8.14](08-effects.md#814-グラデーションとパターン)） |
| オブジェクト | `{ tone: { density: 30%, lpi: 60 } }` | 詳細な指定 |

### 3.4.10 線（Stroke）

```yaml
stroke:
  width: 0.3mm
  color: black
  pen: g-pen
  style: solid        # solid | dashed | dotted | double | none
```

省略記法: `stroke: 0.3mm`、`stroke: 0.3mm dashed`、`stroke: 0.5mm #333 double`、`stroke: none`。空白区切りで、長さ・スタイル名・色を任意の順で並べる。

### 3.4.11 領域（Region）

効果やトーンを適用する範囲を表す。

| 形式 | 例 | 意味 |
|---|---|---|
| キーワード | `panel`、`page`、`trim`、`bleed`、`baseFrame` | コマ全体、ページ全体など |
| 矩形 | `{ rect: [0, 0, 100%, 40%] }` | 基準領域内の矩形 |
| 楕円 | `{ ellipse: [50%, 50%, 30%, 20%] }` | 中心と半径 |
| 多角形 | `{ polygon: [[0, 0], [100%, 0], [60%, 100%]] }` | 頂点の列 |
| パス | `{ path: "M 0 0 L 10 0 ..." }` | SVG のパス構文（単位は基準領域の mm） |
| 帯 | `{ band: { side: top, size: 35% } }` | 基準領域の辺に沿った帯 |
| 要素 | `{ element: taro1, mode: alpha }` | 要素の形。`mode` は `bbox`（外接矩形）、`shape`（輪郭）、`alpha`（画像の不透明部分） |
| 和 | `{ union: [ ... ] }` | 複数領域の和 |
| 差 | `{ subtract: [ A, B ] }` | A から B を除いた領域 |
| 反転 | `{ invert: R }` | 基準領域から R を除いた領域 |

領域には `feather`（境界のぼかし幅、長さ）を付けられる。ぼかしは、モノクロ出力では網点化される（[10.2](10-color-and-output.md#102-モノクロ化の規則)）。

## 3.5 単位

| 単位 | 名称 | mm 換算 | 主な用途 |
|---|---|---|---|
| `mm` | ミリメートル | 1 | 既定の単位 |
| `cm` | センチメートル | 10 | |
| `in` | インチ | 25.4 | |
| `pt` | ポイント | 25.4 / 72（≒ 0.3528） | 文字サイズ |
| `px` | ピクセル | 25.4 / `page.dpi` | Web 向けのドキュメント |
| `Q` | 級 | 0.25 | 写植の文字サイズ |
| `H` | 歯 | 0.25 | 写植の字送り・行送り |
| `em` | 全角 | 現在の文字サイズ | 文字に関する余白・間隔 |
| `%` | 割合 | 文脈による | 座標・サイズ |
| `lpi` | 線数 | - | トーンの線数（トーンの指定でのみ使う） |

- 単位のない数値は `page.units` の単位とみなす。`page.units` の既定値は、判型が mm で定義されている場合は `mm`、px で定義されている場合（SNS 向けプリセットや `[1080px, 1350px]`）は `px` である。
- `px` の換算に使う `page.dpi` の既定値は [4.5](04-pages-and-panels.md#45-ページのプロパティ) に従う。px で判型を定義したページは、Web 向けのプロファイル（`web`、`sns`、`preview`、`draft`）でも判型の画素数のまま出力する（[10.7](10-color-and-output.md#107-出力プロファイル)）。
- `em` は文字の文脈（吹き出しの `padding`、`letterSpacing` など）でのみ使える。それ以外で使った場合はエラー（`UNIT_NOT_ALLOWED`）。

### 3.5.1 既定値の寸法の扱い

組み込みの既定値は B5 判を基準に定め、**仕上がりの短辺の長さに比例して拡大・縮小**する（B5 の短辺は 182 mm）。見開きページでは 1 ページ分の短辺を使う。たとえば、吹き出しの線幅の既定値 0.25 mm は、A4 判（短辺 210 mm）では約 0.29 mm、1080 × 1350 px（96 dpi で短辺約 286 mm）の SNS 向けページでは約 0.39 mm（約 1.5 px）になる。これにより、判型を変えても見た目の比率が保たれる。

- 比例させるもの: 線幅、文字サイズ、間白、基本枠の余白の既定、吹き出しの余白（`em` 以外）・しっぽの寸法とその制限値・最小／最大サイズの絶対値、`inset`、効果の線幅・間隔・長さ、漫符の大きさ、手描きの揺らぎの振幅と波長、ノンブルの位置と大きさ。
- 比例させないもの: 塗り足し、安全領域、トンボ（断裁の精度で決まる物理量）、`pen.minWidth`・`pen.tipWidth`（印刷で線が飛ばないための下限）、トーンの線数、`hand.resolution`。
- 比例で求めた既定の文字サイズが 8 Q（2 mm）を下回る場合は 8 Q とする。
- 利用者が明示した値は比例させない。

## 3.6 座標系

| 座標系 | 原点 | 基準領域（% の基準） | 使う場所 |
|---|---|---|---|
| ページ座標 | 仕上がりの左上 | 仕上がり | ページの `layers`、`coords: page` の要素 |
| 基本枠座標 | 基本枠の左上 | 基本枠 | 自由配置のコマの `box` / `polygon` |
| コマ座標 | コマの表示領域の左上 | コマの表示領域 | コマの `layers`（既定） |
| 要素座標 | 要素の外接矩形の左上 | 要素の外接矩形 | 吹き出しのテキスト位置の微調整など |

- y 軸は下向き、x 軸は右向きとする。読み方向（右から左）によって座標系は反転しない。
- **コマの表示領域**とは、コマの多角形と仕上がりの共通部分の外接矩形である。断ち切りのコマでも、`50%` は見えている範囲の中央になる。
- 塗り足しの領域はページ座標で負の値、または仕上がりの寸法を超える値になる。
- 要素は `coords` で座標系を切り替えられる（[5.3](05-elements-and-images.md#53-配置)）。

## 3.7 ID と参照

### 3.7.1 ID

- ページ、コマ、要素には `id` を付けられる。ID はドキュメント全体で一意でなければならない（`ID_DUPLICATE`）。
- 形式は、文字（Unicode の文字を含む）またはアンダースコアで始まり、文字・数字・`_`・`-` が続く文字列とする。`.` は参照の区切りに使うため含められない。
- 位置キーワード（`center`、`top-left` など）、領域キーワード（`panel`、`page` など）、しっぽの種類名（`wedge`、`bubbles`、`line`、`zigzag`）、`auto`、`none` は ID に使えない（`ID_RESERVED`）。省略記法 `tail: <文字列>`（[3.9.2](#392-プロパティ)）で種類名と参照を区別するためである。
- 素材のアンカー名・領域名にも、位置キーワードは使えない（`<ID>.top` などの参照と区別するため）。
- ID を省略した場合は自動で付与する。自動 ID は、明示的な ID をすべて集めた後に、リストの順番だけから決める（レイアウトの結果には依存しない）。

| 対象 | 自動 ID の形式 | 例 |
|---|---|---|
| ページ | `p<pages のリストでの順番>`（見開きも 1 つと数える） | `p3` |
| コマ | `<ページ ID>-k<panels のリストでの順番>` | `p3-k2` |
| 要素 | `<親の ID>-<種類><同じ親の中での同じ種類の順番>` | `p3-k2-balloon1` |
| `dialogue` から展開した吹き出し | `<コマ ID>-d<行の番号>` | `p3-k2-d1` |

- 自動で作った ID が明示的な ID と衝突する場合は、自動で作った側の末尾に `_2`、`_3` … を付ける。
- `rows` と `split` のコマ割りでは `panels` を読み順に割り当てるため、コマの自動 ID の番号は読み順と一致する。

> 自動 ID は、要素やページの追加・削除で後続の ID が変わる。とくにページの自動 ID はコマ・要素の自動 ID の接頭辞になるため、ページを 1 枚挿入すると、それ以降のページで明示的な ID を持たない要素の線がすべて描き直される。ID はシードの導出に使うため（[9.2](09-hand-drawn.md#92-乱数とノイズ)）、線の形を固定したいページと要素には明示的に ID を付けることを推奨する。`mangacli init` の雛形は、ページに ID を付けた形で作る。

### 3.7.2 参照

| 参照の形式 | 解決先 |
|---|---|
| `<ID>` | 要素・コマ・ページの外接矩形の中心（点として使う場合）、または要素そのもの |
| `<ID>.<アンカー名>` | 画像要素の素材に定義したアンカー（[3.14](#314-assets)） |
| `<ID>.<領域名>` | 画像要素の素材に定義した領域の中心（点として）または領域（領域として） |
| `<ID>.<位置キーワード>` | 要素の外接矩形の 9 点 |
| `<キャラクター ID>` | 同じコマの中で `character` がそのキャラクターである最初の画像要素（ページの `layers` に置いた要素からの参照では、同じページのコマを読み順に探して最初に見つかった画像要素）。点として使う場合は、そのキャラクターの `anchorPriority`（既定 `[mouth, face]`）の順で最初に見つかったアンカー、なければ外接矩形の上辺中央 |

- 要素の ID とキャラクター ID が同じ場合は、要素の ID を優先する。
- 参照先が見つからない場合はエラー（`REF_NOT_FOUND`）とする。
- 異なるページの要素は参照できない（`REF_CROSS_PAGE`）。
- 参照は循環してはならない（`REF_CYCLE`）。例: 吹き出し A の位置が B に依存し、B の位置が A に依存する。

## 3.8 スタイルと既定値のカスケード

要素のプロパティの値は、次の順に重ね合わせて決める。後のものが優先する。

1. 組み込みの既定値
2. 設定ファイルの `defaults`
3. ドキュメントの `defaults`（インポートしたファイルの `defaults` を合成したもの）
4. インクルードしたファイルの `defaults`（そのファイルのページのみ）
5. ロケールの `defaults`（言語を指定してレンダリングする場合、P1）
6. ページの `defaults`
7. コマの `defaults`（グループの子では、さらに外側から内側へグループの `defaults`）
8. キャラクターの設定（`who` を持つ吹き出しには `balloon`、`who` を持つ地の文字には `text`）
9. 発話の種類 `as` に対応するスタイル（[6.13](06-balloons.md#613-組み込みスタイル)）
10. キャラクターの `voice` の、その発話の種類の設定
11. `style` に列挙したスタイル（列挙順に重ねる）
12. 要素自身に書いたプロパティ

スタイルの定義は、組み込みスタイル → 設定ファイルの `styles` → ドキュメントの `styles`（インポートを含む）→ ロケールの `styles` の順に、同じ名前ごとに合成したものを使う。フォントの登録も同様に、設定ファイル → ドキュメント → ロケールの順に、同じ名前を上書きする。

#### 手描き設定とシード

- ドキュメント・ページ・コマの `hand` は、その範囲のすべての要素に対する既定値として扱い、同じ階層の種類ごとの `defaults` より前に重ねる。たとえばコマの `hand` はカスケードの段階 7 の先頭に入り、コマの `defaults.balloon.hand` はその後に重なる。設定ファイル・ドキュメントの `hand` も同様に段階 2・3 の先頭に入る。
- `hand` の値は、合成の前にプリセットを展開した完全なオブジェクトにする。`preset` または `roughness` を含む `hand` は、それより前の段階の `hand` を**置き換える**（部分的に合成しない）。`preset` も `roughness` も含まない `hand` は、前の段階の値に合成する。これにより、外側で `wobble` を明示していても、内側で `hand: loose` と書けば `loose` の値になる。
- `seed` はカスケードせず、要素・コマ・ページ・ドキュメントのうち最も近い階層で指定された値を使う（[9.2.2](09-hand-drawn.md#922-シードの導出)）。

### 3.8.1 合成の規則

- オブジェクトは再帰的に合成する。
- リストは置き換える（連結しない）。
- スカラーは置き換える。
- `null` を書くと、それより前の段階の値を取り消し、組み込みの既定値に戻す。
- 省略記法は、合成の前に正規形へ展開する。展開後のオブジェクトには、省略記法に書かれた項目だけが含まれる。たとえば要素の `stroke: 0.4mm` とスタイルの `stroke: { style: dashed }` を合成すると `{ width: 0.4mm, style: dashed }` になる。
- `%` などの相対値は、合成の後、レイアウトの段階で解決する。
- 倍率のプロパティ（`fontScale`、`tail.widthScale` など）は、合成した値に対して最後に掛ける。複数の段階で指定した場合は、掛け合わせずに最も後の段階の値を使う。

### 3.8.2 例

```yaml
defaults:
  balloon:
    stroke: { width: 0.25mm, pen: g-pen }
    fontSize: 13Q

styles:
  big:
    fontSize: 18Q
    stroke: 0.35mm

pages:
  - panels:
      - defaults:
          balloon: { font: dialogue }
        layers:
          - balloon: うるさい！
            style: big
            as: shout
```

この吹き出しの値は、組み込みの既定値 → ドキュメントの `defaults.balloon` → コマの `defaults.balloon` → スタイル `shout`（`as` による）→ スタイル `big` → 要素自身の順に重ねて決まる。結果は次のとおりである。

| プロパティ | 値 | 由来 |
|---|---|---|
| `shape` | トゲ | `shout` |
| `stroke.width` | 0.35 mm | `big` |
| `stroke.pen` | G ペン | ドキュメントの `defaults.balloon` |
| `fontSize` × `fontScale` | 18 Q × 1.25 = 22.5 Q | `fontSize` は `big`、`fontScale` は `shout` |
| `font` | `shout` ロール（未登録なら `dialogue`、[7.3.3](07-text.md#733-ロール)） | `shout`（コマの `defaults.balloon.font` より後の段階） |

## 3.9 省略記法

利用者が短く書けるように、次の省略記法を用意する。省略記法は、検証の前に正規形へ展開する（[2.2](02-architecture.md#22-処理パイプライン)）。

### 3.9.1 要素

`type` を省略し、種類名をキーとして主要な値を書ける。

| 省略形 | 正規形 |
|---|---|
| `- image: taro` | `{ type: image, src: taro }` |
| `- balloon: こんにちは` | `{ type: balloon, text: こんにちは }` |
| `- text: 翌朝` | `{ type: text, text: 翌朝 }` |
| `- sfx: ドン` | `{ type: sfx, text: ドン }` |
| `- effect: focus-lines` | `{ type: effect, kind: focus-lines }` |
| `- mark: sweat` | `{ type: mark, kind: sweat }` |
| `- draw: arrow` | `{ type: draw, kind: arrow }` |
| `- tone: 30%` | `{ type: fill, paint: "tone(30%)" }` |
| `- group: [ ... ]` | `{ type: group, children: [ ... ] }` |
| `- scatter: sparkle` | `{ type: scatter, items: [{ mark: sparkle }] }`（漫符の種類名なら `mark`、それ以外は素材名として `asset`） |

規則:

1. `type` がある場合は `type` に従う。
2. `type` がない場合は、上表の種類名のキーを `image`、`balloon`、`sfx`、`text`、`effect`、`mark`、`draw`、`tone`、`group`、`scatter` の順に探し、最初に見つかったものを種類とする。
3. 種類名のキーの値はスカラー（`group` はリスト、`scatter` はスカラーまたはリスト）でなければならない。
4. 種類名のキーと、その種類の主要なプロパティを同時に書いた場合（例: `balloon: やあ` と `text: やあ`）はエラー（`SCHEMA_SHORTHAND_CONFLICT`）とする。

### 3.9.2 プロパティ

| プロパティ | 省略形 | 正規形 |
|---|---|---|
| `stroke` | `0.3mm dashed` | `{ width: 0.3mm, style: dashed }` |
| `stroke` / `border` | `none` | `{ style: none }` |
| `shape` | `spike` | `{ kind: spike }` |
| `tail` | `wedge`、`bubbles`、`line`、`zigzag`、`none`（種類名） | `{ kind: <種類名> }` |
| `tail` | `taro1.mouth`（種類名以外の文字列・点） | `{ to: taro1.mouth }` |
| `hand` | `loose` | `{ preset: loose }` |
| `hand` | `false` | `{ preset: clean }` |
| `pen` | `g-pen` | `{ preset: g-pen }` |
| `outline` | `1mm white` | `[{ width: 1mm, color: white }]` |
| `bleed`（コマ） | `top` | `[top]` |
| `bleed`（コマ） | `all` | `[top, right, bottom, left]` |
| `padding` | `1em` | `[1em, 1em]`（縦, 横） |
| `assets.<名前>` | `./a.png` | `{ src: ./a.png }` |
| `fonts.<名前>` | `./a.ttf` | `{ src: ./a.ttf }` |
| `fonts.<名前>` | `gothic`（拡張子なし） | `{ alias: gothic }` |
| `fonts.<名前>` | `catalog:zen-kaku-gothic-new@700` | `{ catalog: zen-kaku-gothic-new, weight: 700 }` |
| `layout` | `{ rows: [[1], [2, 1]] }` | 各段を `{ cols: [...], height: 1 }` に展開 |
| `dialogue` の行 | `- taro: えっ` | `{ who: taro, text: えっ }` |
| 塗り | `tone(30%, 60lpi)` | `{ tone: { density: 30%, lpi: 60 } }` |

## 3.14 assets

素材画像を名前付きで登録する。

```yaml
assets:
  school: ./assets/bg/school.png          # 省略形

  taro-surprised:
    src: ./assets/taro/surprised.png
    kind: art                             # art | lineart | background | photo | texture
    ppi: 600
    character: taro
    anchors:
      mouth: [612, 540]                   # 素材の画素座標
      eyes: [598, 410]
    regions:
      face: [470, 300, 290, 330]          # [x, y, 幅, 高さ]（画素）
      avoid: [300, 600, 500, 900]
```

| キー | 型 | 既定値 | 説明 |
|---|---|---|---|
| `src` | パス \| URL \| data URI | 必須 | 素材のファイル。URL は許可設定が必要（[2.13](02-architecture.md#213-セキュリティ)） |
| `kind` | `art` \| `lineart` \| `background` \| `photo` \| `texture` | `art` | 素材の性質。合成方法とモノクロ化の既定値を決める（下表） |
| `ppi` | 数値 | ファイルの解像度情報、なければ `page.dpi` | 素材の解像度。`fit: none` のときの実寸と、解像度不足の警告に使う |
| `character` | キャラクター ID | - | この素材に描かれている人物。参照（[3.7.2](#372-参照)）と `dialogue` のしっぽの向きに使う |
| `anchors` | Map\<名前, [x, y]\> | - | 素材の画素座標で表した名前付きの点（P0） |
| `regions` | Map\<名前, Rect\> | - | 素材の画素座標で表した名前付きの矩形（P1）。`face` と `avoid` は自動配置で避ける領域として使う |
| `crop` | Rect | - | 素材の一部だけを使う（画素） |
| `filters` | Filter[] | - | 常に適用するフィルタ（[5.6](05-elements-and-images.md#56-フィルタ)） |
| `whiteToAlpha` | 真偽値 \| 0〜1 | `false` | 白を透明にする。数値はしきい値。白背景の線画スキャンに使う |
| `blend` | BlendMode | `kind` による | 既定の合成モード |

| `kind` | 合成の既定値 | モノクロ出力での既定の扱い |
|---|---|---|
| `art` | `normal` | グレー → 網点化 |
| `lineart` | `multiply` | 2 値化（しきい値 50 %） |
| `background` | `normal` | グレー → 網点化 |
| `photo` | `normal` | グレー → 網点化（線数 65 lpi） |
| `texture` | `multiply` | グレー → 網点化 |

素材の画像形式は、PNG、JPEG、WebP、AVIF、GIF（最初のフレーム）、TIFF（最初のページ）、SVG に対応する。SVG は出力解像度でラスタ化して扱う。

## 3.15 characters

```yaml
characters:
  taro:
    name: 太郎
    color: "#3a6ea5"
    anchorPriority: [mouth, face]
    balloon:
      stroke: { width: 0.25mm }
    voice:
      shout: { shape: { kind: spike, count: 26 } }
```

| キー | 型 | 説明 |
|---|---|---|
| `name` | 文字列 | 表示名。セリフ一覧（[10.12](10-color-and-output.md#1012-付随出力)）とデバッグ表示に使う |
| `color` | Color | キャラクターの識別色。デバッグ表示（話者の色分け）とセリフ一覧に使う。吹き出しや文字の色には自動で適用しない |
| `anchorPriority` | 文字列[] | しっぽの向き先として探すアンカー名の順序。既定 `[mouth, face]` |
| `balloon` | 吹き出しのプロパティ | このキャラクターの吹き出しの既定値（カスケードの段階 8） |
| `text` | 文字要素のプロパティ | このキャラクターの `text` 要素（`who` を持つもの）の既定値（段階 8） |
| `voice` | Map\<発話の種類, 吹き出しのプロパティ\> | 発話の種類ごとの上書き（例: このキャラクターの叫びだけトゲを多くする）。カスケードの段階 10 |

## 3.16 styles

```yaml
styles:
  narration-box:
    for: balloon
    shape: rect
    fill: white
    stroke: 0.2mm
    writing: vertical
    font: narration
  night:
    extends: narration-box
    fill: black
    color: white
```

| キー | 型 | 説明 |
|---|---|---|
| `for` | 要素の種類 \| 要素の種類[] | 適用対象を限定する。指定した場合、対象外の要素に適用するとエラー（`STYLE_TYPE_MISMATCH`）、対象の種類にないキーを含むとエラー |
| `extends` | スタイル名 \| スタイル名[] | 継承元。継承元を先に重ね、その上に自身を重ねる。循環はエラー（`STYLE_CYCLE`） |
| その他 | 要素のプロパティ | 適用するプロパティ |

- `for` を省略したスタイルは、複数の種類の要素に適用できる。適用先の種類に存在しないキーは無視し、情報（`STYLE_KEY_NOT_APPLICABLE`、info）を出す。どの種類にも存在しないキーはエラーとする。
- 組み込みスタイル（`say`、`think`、`shout` など、[6.13](06-balloons.md#613-組み込みスタイル)）と同名のスタイルを定義すると、組み込みスタイルの上に重ねて合成する。

## 3.17 defaults

要素の種類ごとの既定値を書く。トップレベル、ページ、コマに書ける。

```yaml
defaults:
  panel:
    border: { width: 0.5mm }
  balloon:
    font: dialogue
    fontSize: 13Q
  text:
    font: narration
  effect:
    "*": { color: black }
    focus-lines: { count: 180 }
  mark:
    sweat: { fill: white }
```

| キー | 対象 |
|---|---|
| `panel` | コマ（枠線、背景など） |
| `image`、`balloon`、`text`、`sfx`、`fill`、`draw`、`group`、`scatter` | 各種類の要素 |
| `effect` | 効果。`"*"` は全種類、それ以外は `kind` ごと |
| `mark` | 漫符。`"*"` は全種類、それ以外は `kind` ごと |

## 3.18 インポートとインクルード

（P1）

### 3.18.1 インポート

共有の定義を別ファイルから取り込む。

```yaml
imports:
  - ./shared/characters.yaml
  - ./shared/styles.yaml
```

- インポートするファイルは、`fonts`、`fontSet`、`assets`、`characters`、`styles`、`defaults`、`hand`、`seed` 以外のトップレベルキーを持ってはならない（`mangacli` は任意）。
- 取り込みはリストの順に行い、各マップをキー単位で合成する。同じキーが複数のファイルにある場合は後のものが優先する。エントリのドキュメント自身の定義が最も優先する。上書きが起きた場合は情報（`IMPORT_OVERRIDE`）を出す。
- インポートは入れ子にできる。循環はエラー（`IMPORT_CYCLE`）。

### 3.18.2 インクルード

ページの並びを別ファイルから取り込む。

```yaml
pages:
  - include: ./chapters/ch01.yaml
  - id: interlude
    type: blank
  - include: ./chapters/ch02.yaml
```

- インクルードするファイルは、ページのリスト、または `pages` キーを持つマップでなければならない。後者の場合、そのファイルは `defaults`（そのファイルのページにだけ適用する。カスケードの段階 4）を持てる。
- インクルードしたファイル内の相対パスは、そのファイルのディレクトリを基準に解決する。

## 3.19 スキーマのバージョンと互換性

- `mangacli` キーの値がスキーマのメジャーバージョンを表す。現行は `1`。
- 同じメジャーバージョンの中では、キーの追加のみを行い、既存のキーの意味は変えない。
- 既存のキーの意味を変える場合はメジャーバージョンを上げ、旧バージョンのドキュメントを変換するコマンド `mangacli migrate` を提供する（P1）。
- ライブラリが対応しないバージョンのドキュメントはエラー（`SCHEMA_UNSUPPORTED_VERSION`）とする。
- 非推奨になったキーを使った場合は警告（`SCHEMA_DEPRECATED`）を出す（[14.8](14-quality.md#148-版の管理)）。

### 3.19.1 エンジンのバージョン（engine）

スキーマのバージョン（`mangacli`）がキーの意味を表すのに対し、エンジンのバージョン（`engine`）は**同じ記述からどんな結果が得られるか**を表す。

- 次のものを変更する場合は、エンジンのバージョンを上げる。
  - 手描き化のアルゴリズム（揺らぎ、線幅、分解、形状レベルの不規則さ）
  - 組み込みの既定値（寸法、色、プリセットの数値、`autoPlace`・`wrap` などの既定の方法）
  - レイアウト・組版・自動配置のアルゴリズム（改行位置や配置の結果が変わるもの）
  - 効果・トーン・漫符の生成方法
- `engine` を明示したドキュメントは、ライブラリを更新しても、そのバージョンの結果を再現する。古いエンジンは、少なくとも次のメジャーバージョンまで維持する。
- `engine` を省略した場合は、そのライブラリの最新のエンジンを使う。`mangacli init` は、その時点の番号を書き込んだドキュメントを作る。
- 1.0 より前（0.x）のエンジンは互換性を保証しない。たとえば、自動配置（P1）を実装する前の既定の配置方法は流し込みであり、実装した時点でエンジンのバージョンが上がる。


## 3.20 JSON Schema とエディタ補完

- スキーマから JSON Schema（Draft 2020-12）を生成し、パッケージに同梱する（`mangacli/schema.json`）。`mangacli schema` コマンドでも出力できる。
- JSON Schema は、省略記法と正規形の両方を受け付ける。
- 各キーに `description`（日本語・英語）と既定値を付け、エディタの補完と説明表示に使えるようにする。
- YAML Language Server での利用例:

```yaml
# yaml-language-server: $schema=./node_modules/mangacli/schema.json
mangacli: 1
```

- プラグインが追加した形状・効果のパラメータも JSON Schema に含められるように、`mangacli schema --config <設定ファイル>` はプラグインを読み込んでから生成する。
