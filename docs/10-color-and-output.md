# 10. 色と出力

## 10.1 カラーモデル

色について、ドキュメントが持つ**色の意図**と、出力時の**カラーモード**を分ける。

| 区分 | キー | 値 | 意味 |
|---|---|---|---|
| 色の意図 | `page.color` | `mono`（既定）\| `color` | 作品がモノクロ（ベタ・トーン）かカラーか。既定値（`dpi`、トーンの描画、検証）の選択に使う |
| カラーモード | 出力の `colorMode` | `color` \| `gray` \| `mono` | 出力画像の色。`gray` は 8 ビットのグレースケール、`mono` は 1 ビット（2 値） |

| 意図 ＼ 出力 | `color` | `gray` | `mono` |
|---|---|---|---|
| `mono` | RGB で出力（内容は白黒） | グレースケール（トーンは網点または平らなグレー） | 2 値（トーンは網点） |
| `color` | RGB で出力 | 輝度に変換 | 輝度に変換し、網点化して 2 値 |

- 色空間は sRGB とする。素材の埋め込みプロファイルは読み込み時に sRGB へ変換する。
- 合成は sRGB の値のまま行う（一般的な描画ソフトと同じ）。
- CMYK・特色は扱わない（[1.4](01-overview.md#14-非ゴールスコープ外)）。

## 10.2 モノクロ化の規則

`gray` と `mono` の出力では、色を次の規則で変換する。

### 10.2.1 輝度

- 線形の輝度 Y_lin は、sRGB の値を線形化し、Rec. 709 の係数（0.2126, 0.7152, 0.0722）で合成した値（0〜1）とする。
- グレーの値 Y は、Y_lin を sRGB のガンマで再び符号化した値とする。`gray` の出力ではこの値を書き出す。
- 色・グレーを網点の濃度に変換するときは、既定で d = 1 − Y_lin とする（`output.mono.toneCurve: linear`）。網点の面積率は紙の反射率に線形に効くため、この変換で、網点化した結果を離れて見たときの明るさが元の色と一致する。たとえば sRGB で 50 % のグレー（`#808080`）は濃度約 79 % の網点になる。
- `output.mono.toneCurve: perceptual` を指定すると d = 1 − Y とする（グレーの値をそのまま「K %」として扱う、作画ソフトの一般的な網点化と同じ）。中間調が明るめになる。
- トーンの塗り（`tone(30%)` など）の濃度は網点の面積率そのものであり、この変換の対象ではない。

### 10.2.2 要素ごとの変換

| 対象 | `gray` | `mono` |
|---|---|---|
| 単色 | Y のグレー | Y ≥ 0.95 は白、Y ≤ 0.05 は黒、それ以外は濃度 d（10.2.1）のトーン（`output.mono.lpi`、既定 60 lpi） |
| グラデーション | 輝度のグラデーション | 濃度 d のトーングラデーション |
| トーン | 網点または平らなグレー（10.3） | 網点 |
| 画像（`kind: lineart`） | グレー | しきい値 50 % で 2 値化 |
| 画像（その他） | グレー | グレーにしてから網点化（`output.mono.imageLpi`、既定 60 lpi。`photo` は 65 lpi）。`output.mono.images: dither` で誤差拡散にできる |
| 半透明（`opacity` < 1、ソフトマスク、`feather`、ぼかし、影、ぼかし枠） | そのまま合成 | アルファを網点化してから合成 |

- 線（効果線、吹き出しの線など）に `opacity` を指定すると、2 値の出力では線が網点になり、点線のように見える。モノクロ原稿で線を薄く見せたい場合は、`opacity` ではなく線幅を細くするか、線の本数を減らす。

### 10.2.3 2 値出力の手順

1. 連続階調を持つもの（上表で「網点化」とあるもの）は、**要素ごとに**、出力解像度の画素格子に揃えて網点化してから合成する。
2. 残りの要素（線、ベタ、白、網点）は、アンチエイリアスを有効にして合成する。
3. 合成結果を、しきい値 50 % で 2 値化する。

この手順により、線の縁の中間調が網点化されて汚れることを防ぐ。

## 10.3 トーンの描画

出力の `toneRendering` で、トーンの描き方を選ぶ。

| 値 | 処理 |
|---|---|
| `dots` | 網点で描く |
| `flat` | 網点を離れて見たときと同じ明るさの平らな色で描く。トーンの色 C、下地の色 B、濃度 d のとき、線形の色空間で d × C + (1 − d) × B を求めて sRGB に戻した色（白地に黒の 30 % のトーンは、sRGB で約 85 % のグレー） |
| `auto` | 出力解像度での網点の格子の大きさが 6 画素以上なら `dots`、未満なら `flat` |

- `mono` の出力では常に `dots` とする（`flat` を指定した場合は警告 `OUTPUT_TONE_FORCED_DOTS`）。
- Web 向けの低解像度の出力で網点を描くと、画素格子との干渉でモアレが出る。Web 向けのプロファイルは `auto` を既定とする。
- `auto` の判定はトーンごとに行う。

## 10.4 出力形式

| `format` | 拡張子 | カラーモード | 透過 | 優先度 | 備考 |
|---|---|---|---|---|---|
| `png` | `.png` | `color`、`gray`、`mono` | `color`、`gray` | P0 | `mono` は 1 ビットのグレースケール PNG |
| `jpeg` | `.jpg` | `color`、`gray` | × | P0 | `mono` は不可（`OUTPUT_MODE_UNSUPPORTED`） |
| `webp` | `.webp` | `color`、`gray` | ○ | P0 | 可逆・非可逆。WebP にはグレースケールの形式がないため、`gray` は R = G = B の RGB として保存する。非可逆の WebP は色差を必ず間引く（4:2:0）ため、線画には `lossless: true` を推奨する |
| `avif` | `.avif` | `color`、`gray` | ○ | P1 | |
| `tiff` | `.tif` | `color`、`gray`、`mono` | `color`、`gray` | P1 | 印刷入稿向け。`mono` は CCITT G4 圧縮 |
| `pdf` | `.pdf` | `color`、`gray`、`mono` | - | P1 | 複数ページ（10.4.3） |
| `svg` | `.svg` | `color`、`gray` | ○ | P1 | ページごと（10.4.4） |
| `psd` | `.psd` | `color`、`gray` | ○ | P2 | 分版をレイヤーとして出力 |

### 10.4.1 ラスタ形式の設定

| キー | 形式 | 既定値 | 説明 |
|---|---|---|---|
| `quality` | jpeg、webp、avif | `92` | 品質（1〜100） |
| `lossless` | webp | `false` | 可逆圧縮 |
| `chroma` | jpeg | `4:4:4` | 色差の間引き。線画のにじみを避けるため既定は間引きなし |
| `compression` | png | `6` | 圧縮レベル（0〜9） |
| `tiffCompression` | tiff | `color`・`gray` は `lzw`、`mono` は `ccitt4` | 圧縮方式 |

- PNG・TIFF・JPEG には、解像度（dpi）を埋め込む。
- sRGB の情報（PNG の `sRGB` チャンク、JPEG の ICC プロファイル）を埋め込む。

### 10.4.2 解像度の埋め込み

出力画像の解像度情報は、出力に使った `dpi` とする。`width` / `height` で寸法を指定した場合は、仕上がりの物理寸法から逆算した値とする。

### 10.4.3 PDF

（P1）

- 1 ページの漫画を PDF の 1 ページとする。見開きは `spread` の設定（10.9）に従う。
- ページボックス: MediaBox は出力範囲（10.6）、TrimBox は仕上がり、BleedBox は塗り足しとする。
- 線・塗り・文字はベクタとして書き出す。文字はアウトライン化した図形である。
- 画像は出力の `dpi` で縮小して埋め込む（JPEG または Flate）。
- `pdf.raster: true` を指定すると、ページ全体をラスタ化して埋め込む。`mono` の出力では既定で `true` とし、1 ビットの画像（CCITT G4）を埋め込む（網点が多いページのファイルサイズと、印刷所の処理の都合のため）。
- 文書情報に `meta` の題名・作者を設定する。
- 現在の実装（engine 1）は、すべてのページをラスタ化して埋め込む（`mono` は 1 ビット・Flate、`gray`・`color` は 8 ビット・Flate の可逆圧縮）。ベクタでの書き出しは今後の拡張とする。
- すべてのページを 1 つのファイル（`<名前>.pdf`）にまとめる。分版を出力する場合は分版ごとに 1 ファイルとする。
- 検索・コピー用の不可視テキストの埋め込みは P2 とする。

### 10.4.4 SVG

（P1）

- ページごとに 1 ファイルを出力する。`viewBox` は mm、`width` / `height` は mm 単位で書く。
- 画像は既定で data URI として埋め込む。`svg.images: link` で外部ファイルへのリンクにできる。
- 一様なトーンは `<pattern>` で表す。それ以外のトーンは網点を図形として書き出す。現在の実装（engine 1）では、グラデーションのトーンは同じ濃度の変化を持つ連続階調のグラデーションで近似する。
- 画像の縁取り（`outline`）は SVG のフィルター（`feMorphology` による膨張）で表す。
- 表示リストの `tag` を `data-id`、`data-type` 属性として書き出す。Web ページでの対話的な利用に使える。

## 10.5 解像度とサイズ

| キー | 型 | 説明 |
|---|---|---|
| `dpi` | 数値 | 出力解像度。既定は `page.dpi` |
| `scale` | 数値 | `page.dpi` に対する倍率 |
| `width` | 整数（px） | 出力範囲の幅をこの画素数にする（縦横比を保つ） |
| `height` | 整数（px） | 出力範囲の高さをこの画素数にする |

- 優先順位は `width` / `height` → `scale` → `dpi`。`width` と `height` を同時に指定した場合は、両方に収まる最大の大きさとする。
- 画素格子の原点は**仕上がりの左上**とする。仕上がりの画素数は、仕上がりの寸法（mm）÷ 25.4 × dpi を四捨五入した値とする（浮動小数点の誤差を吸収するため、端数が 0.5 ± 10⁻⁶ の範囲にある場合は 0.5 とみなして切り上げる）。
- 塗り足し・トンボの領域の画素数も同じ方法で、それぞれの幅から求める。そのため、塗り足しの実寸と画素数の間には最大 0.5 画素の差がありうる。この方法により、`crop: trim` と `crop: bleed` で、仕上がりの内側の画素は一致する。
- `width` / `height` を指定した場合は、出力範囲の画素数がその値になるように dpi を逆算する。
- 出力 1 ページの画素数が上限（[2.13](02-architecture.md#213-セキュリティ)）を超える場合はエラー（`OUTPUT_TOO_LARGE`）。

## 10.6 出力範囲とトンボ

| `crop` | 出力範囲 | 優先度 |
|---|---|---|
| `trim` | 仕上がり | P0 |
| `bleed` | 塗り足しを含む範囲 | P0 |
| `marks` | 塗り足しの外側にトンボの領域（既定 10 mm）を加えた範囲 | P1 |
| `{ panel: <ID>, margin: <Length> }` | 1 つのコマの外接矩形（`margin` だけ広げる）。コマ単位で SNS に投稿する場合などに使う | P2 |

`crop: marks` のときに描くトンボ:

| 種類 | 内容 |
|---|---|
| 角トンボ | 4 隅に、仕上がり線の延長（内トンボ）と塗り足し線の延長（外トンボ）の 2 本ずつの線 |
| センタートンボ | 各辺の中央に十字の線 |
| 情報（任意） | `marks.info: true` で、トンボの領域にファイル名・ページ番号・出力日時（`SOURCE_DATE_EPOCH` がある場合のみ）を小さく書く |

| キー | 既定値 | 説明 |
|---|---|---|
| `marks.margin` | 10 mm | 塗り足しの外側の余白 |
| `marks.length` | 9 mm | トンボの線の長さ |
| `marks.width` | 0.1 mm | 線幅 |
| `marks.color` | `black` | 線の色 |

## 10.7 出力プロファイル

出力の設定をまとめた名前付きの組である。組み込みのプロファイルを次のとおりとする。

| プロファイル | 用途 | `colorMode` | `dpi` | `crop` | `format` | `toneRendering` | `spread` | `finish` | 印刷用 |
|---|---|---|---|---|---|---|---|---|---|
| `print-mono` | モノクロ原稿の入稿 | `mono` | 600 | `bleed` | `png` | `dots` | `split` | 無効 | ○ |
| `print-gray` | グレースケール原稿の入稿 | `gray` | 600 | `bleed` | `png` | `dots` | `split` | 無効 | ○ |
| `print-color` | カラー原稿の入稿 | `color` | 350 | `bleed` | `png` | `dots` | `split` | 無効 | ○ |
| `web` | Web・SNS への掲載 | 意図による（`mono` → `gray`） | 長辺 2,000 px | `trim` | `png` | `auto` | `joined` | 設定どおり | |
| `sns` | SNS への投稿（容量優先） | 意図による | 長辺 1,600 px | `trim` | `jpeg`（`quality: 90`） | `auto` | `joined` | 設定どおり | |
| `preview` | 確認用 | 意図による | 96 | `trim` | `png` | `auto` | `joined` | 無効 | |
| `draft` | ネーム | `gray` | 150 | `trim` | `png` | `flat` | `joined` | 無効 | |

- 「意図による」は、`page.color` が `mono` なら `gray`、`color` なら `color`。
- 「長辺 2,000 px」は、`width` / `height` のうち長辺の側にこの値を指定することを表す。
- 判型を px で定義したページ（[3.5](03-document-format.md#35-単位)）では、`web`、`sns`、`preview`、`draft` の解像度・寸法の指定を使わず、判型の画素数（`scale: 1`）で出力する。寸法を変えたい場合は `width` などを明示する。
- `print-mono` の既定の形式は PNG とする。印刷所が TIFF や PSD を求める場合は、`format: tiff` を指定したプロファイルを定義する（PSD は P2）。
- `draft` プロファイルは、手描きプリセットを `sketch` にし、素材がない場合にプレースホルダーを描く（`--draft` と同じ）。
- 既定のプロファイルは `web` とする。CLI では `--profile` で選ぶ。
- 「印刷用」のプロファイルでは、ノンブルを描き（[4.13](04-pages-and-panels.md#413-ノンブル) の `show: print`）、解像度不足の警告のしきい値を厳しくする。

### 10.7.1 プロファイルの定義

```yaml
output:
  dir: ./out
  profile: web
  profiles:
    doujin:
      extends: print-mono
      crop: marks
      format: tiff
    x-post:
      extends: sns
      width: 1200
```

| キー | 型 | 説明 |
|---|---|---|
| `extends` | プロファイル名 | 継承元 |
| `format` | 出力形式 \| 出力形式[] | 複数を指定すると、同じページを複数の形式で出力する |
| `colorMode` | `color` \| `gray` \| `mono` | カラーモード |
| `dpi`、`scale`、`width`、`height` | - | 10.5 |
| `crop` | `trim` \| `bleed` \| `marks` | 10.6 |
| `marks` | Marks | 10.6 |
| `toneRendering` | `dots` \| `flat` \| `auto` | 10.3 |
| `spread` | `joined` \| `split` | 10.9 |
| `background` | Paint \| `transparent` | ページの地の上書き（10.15） |
| `separate` | 分版名[] \| Map\<出力名, 分版名[]\> \| `all` \| `false` | 10.10 |
| `finish` | Finish | 10.14 |
| `mono` | `{ lpi, imageLpi, images, toneCurve }` | 10.2 |
| `print` | 真偽値 | 印刷用として扱うか |
| `name` | 文字列 | ファイル名のテンプレート（10.8） |
| `dir` | パス | 出力先 |
| `metadata` | 真偽値 | メタデータを埋め込むか（10.13） |
| `quality`、`lossless`、`chroma`、`compression`、`tiffCompression` | - | 10.4.1 |
| `pdf`、`svg` | - | 10.4.3、10.4.4 |
| `debug` | Debug | 10.11 |
| `emit` | 付随出力の種類[] | 10.12 |

設定は、組み込みのプロファイル → 設定ファイルのプロファイル → ドキュメントの `output` → CLI のオプション（または API の引数）の順に重ねる。

## 10.8 ファイル名と出力先

- `name` の既定値は `"{name}-{page:03}"`。拡張子は形式から自動で付ける。
- 使える置換子:

| 置換子 | 内容 |
|---|---|
| `{name}` | エントリの YAML のファイル名（拡張子を除く）。API では `meta.title` から作った安全な名前、なければ `manga` |
| `{title}` | `meta.title` |
| `{page}` | ノンブルの番号。見開きの `joined` では `{a}-{b}`（例: `004-005`）、`split` では各ページの番号。番号を持たないページ（`countBlank: false` の白ページ、`pageNumbers.enabled: false` の本）では `i` + `{index}`（例: `i007`） |
| `{index}` | ページの通し番号（1 始まり） |
| `{id}` | ページの ID |
| `{side}` | `left` \| `right` \| `spread` |
| `{profile}` | プロファイル名 |
| `{lang}` | 言語 |
| `{sep}` | 分版名（分版出力のみ） |

- `{page:03}` のように、`:` の後に桁数を書くと 0 で埋める。
- テンプレートは `{` で始まるため、YAML では引用符で囲む（例: `name: "{name}-{page:03}"`）。
- 置換後の名前に含まれるパス区切り文字や `..` は `_` に置き換える。
- 1 回のレンダリングの中で、異なるページ・分版・形式が同じファイル名になる場合はエラー（`OUTPUT_NAME_COLLISION`）とし、何も書き出さない（出力の前に判定する）。
- 出力先に既にある同じ名前のファイルは上書きする。`--clean`（P1）を指定すると、出力の前に、出力先にある同じテンプレートに一致するファイルを削除する。
- 出力したファイルの一覧（ページ ID、ファイル名、寸法、内容のハッシュ）を `manifest.json` として書き出せる（`emit: [manifest]`、P1）。

## 10.9 見開きの出力

（P1）

| `spread` | 出力 |
|---|---|
| `joined` | 見開きを 1 枚の画像として出力する |
| `split` | 左右 2 枚に分けて出力する。各ページは、中央側にも塗り足しの幅だけ反対側のページの内容を含む |

## 10.10 分版出力

（P1）要素を種類ごとに分け、それぞれを透過画像として出力する。他の作画ソフトで仕上げる場合や、写植だけを差し替える場合に使う。

| 分版名 | 含む要素 |
|---|---|
| `background` | ページとコマの地 |
| `art` | 画像 |
| `fx` | 効果、塗り、散布、漫符 |
| `frame` | 枠線 |
| `balloon` | 吹き出しの本体としっぽ |
| `text` | 吹き出しの本文、地の文字 |
| `sfx` | 描き文字 |
| `furniture` | ノンブル |

- 要素の `separation` で振り分け先を変えられる（[5.2](05-elements-and-images.md#52-共通プロパティ)）。
- `separate` にマップを書くと、複数の分版を 1 つの出力にまとめられる。たとえば写植と吹き出しを 1 枚にまとめる場合は `separate: { lettering: [balloon, text, sfx], art: [background, art, fx, frame] }` とする（`{sep}` は出力名になる）。
- 各分版は、透過の背景の上に、その分版の要素だけを通常の描画順で合成したものとする。合成モード（`multiply` など）は透過の背景に対して適用する。
- `mono` の分版は、2 値の値を持つ 8 ビットのグレー＋アルファで出力する（1 ビットの画像は透過を持てないため）。
- ファイル名は `name` に `{sep}` を含めるか、既定では `"{name}-{page:03}-{sep}"` とする。

## 10.11 デバッグ出力

### 10.11.1 オーバーレイ

| 項目 | 表示内容 |
|---|---|
| `boxes` | 塗り足し、仕上がり、基本枠、安全領域の線 |
| `panels` | コマの多角形、ID、読み順の番号 |
| `elements` | 要素の外接矩形と ID |
| `text` | 文字の行（列）の範囲、本文の安全領域 |
| `balloons` | しっぽの幾何、本文の安全領域、連結 |
| `order` | 吹き出しの読み順を結ぶ矢印 |
| `grid` | 10 mm 間隔の格子 |
| `autoplace` | 自動配置の候補点の費用の分布（P2） |

- CLI の `--debug`（すべて）または `--debug panels,text` で指定する。
- オーバーレイは半透明の色で描くため、デバッグ出力はカラーモードを `color`、形式を `png` に切り替える。
- オーバーレイの文字は `ui` ロールのフォントで描く。

### 10.11.2 一覧画像（コンタクトシート）

（P1）全ページの縮小画像を、本の見開きの並び（右綴じなら右から左）で 1 枚に並べ、ページ番号と ID を添える。CLI の `--contact-sheet` で出力する。

## 10.12 付随出力

（P1）`emit` で、画像のほかに次のファイルを出力する。

| 種類 | ファイル | 内容 |
|---|---|---|
| `layout` | `{name}.layout.json` | LayoutTree（[2.4.2](02-architecture.md#242-layouttree-の要件)） |
| `ir` | `{name}-{page:03}.ir.json` | 表示リスト（[2.5](02-architecture.md#25-表示リストir)） |
| `transcript` | `{name}.transcript.json`、`{name}.transcript.md` | セリフ一覧（下記） |
| `manifest` | `manifest.json` | 出力したファイルの一覧 |

**セリフ一覧**は、ページ → コマ → 要素の読み順に、吹き出しの本文・地の文字・描き文字を並べたものである。校正、翻訳、代替テキストの作成に使う。

```json
{
  "pages": [
    {
      "id": "p1", "number": 1,
      "items": [
        { "panel": "p1-k1", "id": "p1-k1-d1", "type": "balloon", "who": "taro", "name": "太郎", "as": "say", "text": "えっ!?", "raw": "えっ!?" }
      ]
    }
  ]
}
```

`text` はマークアップを取り除いた文字列（ルビは `東京（とうきょう）` の形）、`raw` は元の文字列である。

## 10.13 メタデータ

- PNG のテキストチャンク、JPEG・WebP の XMP、PDF の文書情報に、題名、作者、著作権表示、生成ソフト（`mangacli <バージョン>`）、ページ ID を書き込む。
- 再現のための情報として、シードとドキュメントのハッシュを書き込む（`mangacli:seed`、`mangacli:source-hash`）。
- 作成日時は書き込まない。`SOURCE_DATE_EPOCH` がある場合だけ、その時刻を書き込む。
- `metadata: false` で、すべてのメタデータを省く。

## 10.15 透過背景

- `background: transparent` を指定すると、ページの地（`page.background`）を描かず、透過にする。
- コマの地（既定 `paper`）は描く。コマの地も透過にする場合は、`defaults.panel.background: none` を指定する。
- 透過に対応しない形式（JPEG、`mono` の PNG・TIFF）で指定した場合はエラー（`OUTPUT_MODE_UNSUPPORTED`）。
