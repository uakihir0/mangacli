# 1. 概要

## 1.1 目的

mangacli（以下「本ライブラリ」）は、漫画の構造（ページ、コマ割り、素材の配置、吹き出し、セリフ、文字、効果）を宣言的なドキュメントとして受け取り、日本の漫画として完成した画像を出力する TypeScript 製の npm ライブラリである。次の 2 つの使い方を提供する。

1. **CLI**: YAML ファイルを渡すと、ページごとの画像（PNG など）や PDF を出力する。
2. **ライブラリ**: Node.js アプリケーションに組み込み、TypeScript オブジェクトまたは YAML 文字列から画像のバイト列を得る。

キャラクターや背景などの絵は、利用者が素材画像として与える。本ライブラリは、素材をコマに収め、漫画として仕上げるための要素を手続き的に生成して描画する。生成する要素は、コマ枠、吹き出し、写植、描き文字、集中線などの効果線、スクリーントーン、漫符である。

生成する線や形は、幾何学的に完璧な図形ではなく、**人がペンで描いたように見える**ことを既定とする（[09-hand-drawn.md](09-hand-drawn.md)）。

## 1.2 背景

- 漫画の仕上げ工程（枠線、吹き出し、写植、効果線、トーン）は定型的だが、作業量が多い。
- 汎用の描画ツールで作った吹き出しや効果線は、真円や等幅の直線になりやすく、「機械で作った」印象を与える。
- 日本の漫画には、縦書き、右綴じ、アンチゴチ（かなはアンチック体・漢字はゴシック体の混植）、縦中横、ルビ、間白、断ち切りなどの固有の慣習がある。汎用ツールの既定値ではこれらを満たせない。
- 漫画の構造をテキストで記述できれば、バージョン管理、差分レビュー、翻訳版の制作、プログラムや AI による自動生成ができる。

## 1.3 ゴール

| ID | ゴール |
|---|---|
| G1 | YAML だけで、印刷入稿と Web 掲載の両方に使える品質の漫画ページを出力できる |
| G2 | 出力が手描きの漫画に見える。線の揺らぎ、筆圧による太さの変化、入り抜き、閉じ目のずれ、効果線の不揃いを既定で表現する |
| G3 | 日本の漫画の慣習を既定でサポートする。右綴じ、右から左の読み順、縦書き、禁則処理、縦中横、ルビ、傍点、混植、間白、断ち切り、ノンブル、トンボを含む |
| G4 | 白黒（ベタ・トーン）とカラーを、同じドキュメントから出力できる |
| G5 | 出力が決定的である。同じ入力・同じバージョンからは同じ出力を得る。シードを変えると「描き直した」別の線になる |
| G6 | Node.js アプリ、ビルドパイプライン、サーバーに組み込める API を提供する |
| G7 | 吹き出しの形、効果、漫符、ペン、コマ割りテンプレートをプラグインで追加できる |
| G8 | 誤りを、ファイル名・行・列とともに具体的に報告する。人だけでなくプログラムや AI が YAML を生成・修正できる |

## 1.4 非ゴール（スコープ外）

- キャラクターや背景の絵そのものの生成（画像生成 AI など）。素材は外部から与える。
- GUI エディタの提供。ただし、エディタの実装に必要なレイアウト結果と表示リストは API で提供する（[11-api.md](11-api.md)）。
- 素材画像からの顔・人物の自動検出。吹き出しの自動配置で避ける領域は、利用者が素材のメタデータで与える。
- CMYK・特色の分版や、印刷所ごとの入稿仕様の完全な保証。出力は RGB、グレースケール、2 値までとする。
- アニメーション、モーションコミック。
- 自動翻訳、OCR。
- 脚本からの自動コマ割り。テンプレートの提供までとする。
- 日本語以外の言語固有の組版規則（中国語・韓国語の禁則など）の完全な対応。横書きの欧文は基本的な組版を提供する。

## 1.6 設計原則

1. **宣言的に書く**: 利用者は「何を描くか」を書き、「どう描くか」はエンジンが決める。細かく制御したい場合だけ詳細なパラメータを指定する。
2. **段階的に詳細化できる**: 最小の記述（例: `- balloon: こんにちは`）で妥当な結果が得られる。省略した値には、漫画として自然な既定値を使う。
3. **手描きらしさを既定にする**: 揺らぎや入り抜きは既定で有効にする。幾何学的な線（`hand: clean`）は明示的に選ぶ。
4. **日本の漫画の慣習を既定にする**: 右綴じ、右から左の読み順、縦書き、天揃え、アンチゴチ、間白の比率などを既定値にする。
5. **決定的である**: 乱数はすべてシードから導出し、時刻や環境に依存しない。
6. **解像度に依存しない**: 形状と揺らぎは物理単位（mm）で計算する。プレビュー（低解像度）と本番出力（高解像度）で線の形が一致する。
7. **白黒とカラーを同じソースから出力する**: 色の意図と出力カラーモードを分け、変換規則を明確にする。
8. **拡張できる**: 形状、効果、漫符、ペン、テンプレートを、同じ仕組みのプラグインで追加できる。組み込み機能も同じ仕組みで実装する。
9. **安全である**: ドキュメントはコードを実行しない。ネットワークアクセスは既定で無効にする。ファイル参照はプロジェクトのルート内に制限する。
10. **誤りを具体的に伝える**: 診断には位置、原因、修正の手がかりを含める。
