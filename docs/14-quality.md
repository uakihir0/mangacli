# 14. 品質

## 14.1 テストの方針

| 種類 | 対象 | 道具 |
|---|---|---|
| 単体テスト | 単位、カスケード、参照、幾何、組版、乱数、ストローク、トーン | `vitest` |
| 性質テスト | 幾何と組版の不変条件（14.2.2） | `fast-check` |
| 表示リストのスナップショット | 機能ごとのサンプル | 丸めた JSON の比較 |
| ビジュアルリグレッション | 機能カタログ、サンプル | `pixelmatch` |
| 決定性テスト | 同じ入力の繰り返し、並列数の違い | ハッシュの比較 |
| CLI の結合テスト | コマンド、終了コード、出力ファイル | 子プロセスの実行 |
| 性能テスト | 14.5 の目標 | ベンチマーク |
| 目視の評価 | 手描きらしさ（14.4） | ギャラリー |

テスト用のフォントは、再配布できるライセンス（SIL Open Font License など）のものをリポジトリに含める（テストがネットワークに依存しないようにするため）。

フォントの取得（[7.3.10](07-text.md#7310-フォントのカタログと取得)）は、ローカルの HTTPS のモックサーバーで次を検証する: 取得と配置、ハッシュの不一致の検出、リダイレクトの制限、同時取得の排他、`fontDownload: never` でのエラー、ミラーの置き換え。カタログの各項目の URL とハッシュは、CI で定期的に実際の取得元と照合する（取得元のファイルの消失・変更の検出）。


## 14.2 単体テストと性質テスト

### 14.2.1 単体テストの主な対象

- 単位の解析と換算（`13Q`、`0.3mm`、`%` の基準、px と dpi）
- 省略記法の展開と、カスケードの合成（`null` による取り消し、リストの置き換え）
- 参照の解決と循環の検出
- コマ割り（`rows`、`split`、`slant`、間白、断ち切り）の多角形
- 読み順（自由配置の帯の規則を含む）
- 組版: 禁則、追い出し・追い込み、縦中横、ルビ、傍点、約物の詰め、記号の正規化、マークアップの解析
- 乱数とノイズの値（固定シードでの既知の値との一致）
- ストロークの線幅の関数、入り抜き、輪郭の生成
- ストロークへの分解（角の検出、閉じ目、内側の突き抜けの除去）
- 網点の閾値関数（濃度と面積率の一致）
- モノクロ化の規則
- 文字列の構文（[16](16-grammar.md)）の解析: 付録の各例と、受理・拒否の境界の例を適合テストとして持つ

### 14.2.2 不変条件

| 不変条件 |
|---|
| 吹き出しの本文の安全領域（形状レベルの不規則さと `tilt` を適用した後のもの）は、本文の行の矩形（`padding` を含む）をすべて含む |
| 隣り合うコマの間の距離は、指定した間白以上である（誤差 0.01 mm） |
| 断ち切りの後も、`rows` / `split` のコマは凸多角形である |
| 表示リストの座標に NaN・無限大を含まない |
| 同じ入力・同じシードからは、同じ表示リストが得られる |
| 異なるシードからは、異なる表示リストが得られる |
| 要素 A を変更しても、ID の変わらない他の要素の表示リストは変わらない |
| 網点の面積率は、指定した濃度と ±1.5 % 以内で一致する（十分な広さの範囲で） |
| ストロークの線幅は、`pen.minWidth` 以上（入り抜きの先端を除く） |
| 内側を塗る形のストロークは、形状の内側の縮小領域に入らない |

## 14.3 ビジュアルリグレッションテスト

### 14.3.1 機能カタログ

機能ごとに 1 ページの YAML を用意し、すべてのパラメータの代表的な組み合わせを並べる。カタログは利用者向けのドキュメントの図にも使う。

| カタログ | 内容 |
|---|---|
| `balloons` | すべての形状 × 線のスタイル × 塗り |
| `tails` | しっぽの種類 × 向き × 曲がり、連結 |
| `text-vertical` | 縦書きの約物、縦中横、ルビ、傍点、禁則、混植 |
| `text-horizontal` | 横書き、欧文 |
| `layouts` | `rows`、`split`、`slant`、断ち切り、テンプレート、重ねゴマ |
| `effects` | すべての効果と主なパラメータ |
| `tones` | 濃度・線数・形・グラデーション・境界・削り |
| `marks` | すべての漫符 |
| `hand` | 手描きプリセット・ペンの比較 |
| `color` | カラー・グレー・2 値の比較 |

### 14.3.2 比較の基準

| 比較 | 基準 |
|---|---|
| 表示リスト（丸めた JSON） | 同じ Node.js のメジャーバージョンの中で、±0.001 mm の範囲で一致（プラットフォームに依存しない主たる基準。Node.js のメジャーバージョンごとに基準を持つ） |
| 基準プラットフォーム（Linux x64）のラスタ出力 | バイト列の完全一致（[2.9](02-architecture.md#29-決定性と再現性) の L2） |
| その他のプラットフォームのラスタ出力 | `pixelmatch`（しきい値 0.1）で異なる画素が全体の 0.5 % 以下 |

基準画像の更新は、差分画像をレビューしたうえで明示的なコマンド（`--update`）で行う。

## 14.4 手描き品質の受け入れ基準

### 14.4.1 機械的に測る基準

| 項目 | 基準（`ink` プリセット） |
|---|---|
| 吹き出しの輪郭の線幅の変化 | 最大 / 最小（入り抜きを除く）が 1.2〜1.9（[9.15](09-hand-drawn.md#915-品質の指針) の 0.7〜1.3 倍に対応） |
| 閉じ目の隙間が見える吹き出しの割合 | 機能カタログ全体で 10〜30 % |
| 同じ形状・同じ大きさの吹き出しの形の違い | 異なる ID の 2 つの吹き出しの輪郭のハウスドルフ距離が 0.05 mm 以上 |
| 楕円の吹き出しの、同じ縦横比・同じ `squareness` の超楕円からのずれ | 半径の相対的なずれの最大値が 1〜5 %（`egg` と調和成分による） |
| 本文と輪郭の距離 | 最小で `padding` の 0.5 倍以上 |
| 吹き出しの内側の線 | 本体の内側の縮小領域に黒の画素がない |
| 集中線の間隔の変動係数 | 0.3 以上（等間隔でない） |

### 14.4.2 目視の評価

- 機能カタログとサンプルから、評価用のギャラリーを生成する。
- 漫画の制作経験がある評価者が、次の観点を 5 段階で評価する。マイルストーンの完了条件として、各観点の平均 4.0 以上を目標とする。

| 観点 | 評価の問い |
|---|---|
| 線の自然さ | ペンで描いた線に見えるか。機械的すぎる、または汚すぎることはないか |
| 吹き出しの形 | 手で描いた吹き出しに見えるか。形の歪みは自然か |
| しっぽ | 本体とのつながり、先端の鋭さは自然か |
| 効果線 | 手で描いた集中線・流線に見えるか。束感・不揃いは自然か |
| 写植 | 漫画の写植として読みやすく、慣習に合っているか |
| 全体の印象 | 1 ページとして、手描きの漫画に見えるか |

- 評価の記録とパラメータの変更履歴を残し、既定値の調整の根拠とする。

## 14.5 性能目標

基準環境: Apple M1 相当、または 4 コア・8 スレッドの x64、メモリ 16 GB。フォントの初回読み込みを除く。

| 処理 | 目標 |
|---|---|
| B5・600 dpi・2 値、6 コマ・吹き出し 10・効果 2・全面のトーン 1 の 1 ページ | 3 秒以内 |
| 同じページを 96 dpi でプレビュー | 0.5 秒以内 |
| 同じページのレイアウトと表示リストの生成のみ | 0.3 秒以内 |
| 32 ページ（上記と同程度）を並列数 4 で出力 | 60 秒以内 |
| watch で 1 ページの吹き出しを変更してからプレビューが更新されるまで | 1 秒以内 |
| 600 dpi の B5 を並列数 2 で出力するときの最大メモリ | 1.5 GB 以下 |

性能テストは CI で定期的に実行し、20 % 以上の劣化を検出したら警告する。

## 14.8 版の管理

- パッケージはセマンティックバージョニングに従う。
- ドキュメントのスキーマのメジャーバージョン（`mangacli: 1`）は、パッケージのメジャーバージョンとは独立に管理する（[3.19](03-document-format.md#319-スキーマのバージョンと互換性)）。
- 非推奨にするキーは、少なくとも 1 つのマイナーバージョンの間、警告を出してから削除する（削除はメジャーバージョンで行う）。
- 見た目・レイアウトを変えるアルゴリズムと既定値の変更は、エンジンのバージョン `engine` で管理する（[3.19.1](03-document-format.md#3191-エンジンのバージョンengine)）。
