# 作例づくりの記録 — 吹き出しのデザインと AI での絵の生成

作例「三十一戦目」を作り直したときに分かったことの記録。ライブラリで直したこと、原稿（`manga.yaml`）の書き方のコツ、画像生成 AI で描いた絵を mangacli で漫画にするときのコツをまとめる。

## 1. 吹き出し・写植

### 1.1 直す前の問題

| 問題 | 原因 |
|---|---|
| しっぽが小さな突起にしか見えない | 話者の顔が本体のすぐ横にあると、しっぽを顔の手前で止めるため 2 mm ほどに縮んでいた |
| 別のキャラクターへのしっぽが手前の人物の顔で止まる | しっぽは向き先によらず、画像の `face` 領域（その画像の主役の顔）で止めていた |
| 枠からはみ出した吹き出しが、ページの余白まで飛び出す | 吹き出しの既定が `clip: none` で、外周の辺でも枠線の上に描いていた |
| 「──」が縦書きで横棒 2 本に分かれる | 罫線の `─` をダッシュとして扱わず、縦向きにもつながりもしなかった |
| 叫びの吹き出しのトゲが大きく不揃い | トゲの間隔・深さ・揺らぎが大きすぎた |

### 1.2 ライブラリで直したこと

| 項目 | 今の既定 | 変更前 |
|---|---|---|
| 吹き出しの `clip` | `auto`: コマの間の枠線には重ねて描き、枠の外周を越える場合は枠で切る。切る場合は本文を外周の辺から `max(2.5 bmm, 0.8em)` 内側へ寄せる | `none` |
| しっぽの最短の長さ | 4.5 bmm | 3.2 bmm |
| しっぽの `maxLength` | 本体の短辺の 60 %（4.5〜12 bmm） | 55 %（3.5〜10 bmm） |
| しっぽの付け根の幅 | 本体の短辺の 13 %（1.6〜2.8 bmm） | 10 %（1.1〜2.2 bmm） |
| しっぽを顔で止める条件 | 向き先がその顔の上（30 % 広げた範囲）にある場合だけ。曲がり（`curl`）の中心にも同じ条件 | 常に |
| ダッシュ | `─`・`━` も `―` として扱い、縦書きでは縦向きにして字送りいっぱいに伸ばす（縦用の字形がない書体でも） | `―`・`—` だけ |
| トゲ（`spike`） | 周長 ÷ 5 mm 本、深さ `[0.18, 0.28]`、`angleJitter: 0.2` | ÷ 6 mm、`[0.22, 0.34]`、`0.3` |

### 1.3 少年誌の写植の決まりごと（原稿を書くときの指針）

参考にした商業誌の見開きと、Sogni に描かせた吹き出し付きのページ（`refs/`）から読み取ったもの。

- **本文の大きさ**: B5 のページで 18 bQ 前後（`defaults.balloon.fontSize: 18bQ`）。小さいと吹き出しばかりが目立つ。強調するセリフだけ `fontScale` で大きくする。
- **改行**: 1 列は 4〜7 字。長いセリフは手で `\n` を入れて 2〜3 列にし、吹き出しを丸に近づける。「……」で始まるセリフは「……」だけを 1 列目に置くと間が出る（`"……\n来たか"`）。
- **置き場所**: コマの隅（読み始めの右上か、話者の頭の横）に寄せる。顔・口・手元を覆わない。外周の辺に寄せて **枠で切れる吹き出し** にすると、プロの写植らしくなる（`clip: auto` で自動）。
- **しっぽ**: 短く鋭く、話者の口へ向ける。しっぽが別の人物の頭を横切るなら、吹き出しを話者の側へ移す（しっぽを伸ばして解決しない）。
- **続くセリフ**: 同じ話者の続く 2 つの吹き出しは、少し重ねて輪郭を合成する（`connect: { to: <id>, style: overlap }`）。しっぽは先の吹き出しだけに付ける。
- **ルビ**: 名前などの読みにくい語に付ける（`<ruby=きりしま>霧島</ruby>`）。
- **叫び**: `as: shout`（トゲ）・`as: scream`（爆発）。話者の顔にかからないよう、コマの反対側に置いて枠で切る。
- **自動配置**: `at` を書かなければ顔を避けて置く。狭いコマでは `BALLOON_NO_SPACE` が出て髪や顔に重なることがあるので、絵を見て空の上などに `at` で置く。
- **ナレーション**: 断ち切りのコマでは安全領域の内側に置く（右端に寄せすぎると `TEXT_OUTSIDE_SAFE_AREA`）。

### 1.4 確認の手順

1. `npx mangacli render sample/manga.yaml -p print-mono` で描く（約 10 秒）。
2. ページ全体を見て、読み順・顔の隠れ・しっぽの向きを確認する。
3. 気になるところは拡大して見る（`sharp` で切り出して見る）。しっぽの長さ、枠で切れた吹き出しの残り、ダッシュのつながりは、縮小した絵では分からない。
4. 警告（`BALLOON_NO_SPACE`、`TEXT_OUTSIDE_SAFE_AREA`）は、その吹き出しを絵で確かめる。

## 2. 画像生成 AI の絵を mangacli で使う

文字・吹き出し・効果は mangacli が載せ、AI には絵だけを描かせる。分担をはっきりさせると、絵の選び方も原稿の書き方も決まる。

### 2.1 絵に描かせないもの

- **文字・吹き出し・擬音・コマの枠を描かせない**。mangacli がすべて描くので、絵に描かれたものは邪魔になる。AI の文字は読めず、AI の吹き出しは位置を選べず、枠はコマの枠線と二重になる。プロンプトに「no text, no speech bubbles, no sound effects, no borders, no frames」を入れる。
- **「空けておいて」と頼まない**。「右側を空けて（empty space）」と書くと、白い箱や吹き出しの形を描くことが多い。空けたい側に何が続くか（空、壁、グラデーション）を書く。吹き出しはその上に載る。
- それでも絵の端に細い枠線が出ることがある。コマの枠線は mangacli が描くので、絵の側の枠線は数十 px 切り落としてから使う。
- 絵の中に描かれた箱や文字は、絵を作り直すより画像編集（その部分を周りの背景で埋める）で消す方が早い。構図が変わらないので、測ったアンカーもそのまま使える。

### 2.2 コマに合わせた絵の形

- 画像はコマの塗り足しを含む外接矩形を `fit: cover` で覆い、はみ出した分は切れる。**絵の縦横比はコマの縦横比に近づけて生成する**（横長のコマには 2:1、縦長には 4:5 など）。比が離れているほど、`focus` で選べる範囲が狭くなる。
- 切り取りの中心は `focus`（0〜1 の相対位置）で決める。顔が切れる、吹き出しの場所がなくなる場合は、まず `focus` と `zoom` を動かす。絵を作り直すのはその後。
- 断ち切りのコマ（`bleed`）は、絵が仕上がりの外まで続く前提で構図を考える。ナレーションや本文は安全領域の内側に置くので、絵の主役も端に寄せすぎない。
- 解像度は、印刷（`print-mono`）で `ASSET_LOW_RESOLUTION` が出る。生成の上限で足りない場合は拡大してから使うか、警告を承知で使う。

### 2.3 吹き出しの場所を絵の段階で用意する

- 縦書き・右綴じでは、コマの吹き出しは **右上から読み始める**。最初のセリフがあるコマは、右上を背景（空・壁）にした構図を頼む。
- 話者の頭の横、またはコマの隅に吹き出しを置く。隅に置いた吹き出しは外周の枠で切れる（`clip: auto`）。顔をコマの隅に寄せた絵だと、吹き出しの置き場がなくなる。
- 叫び（トゲ・爆発）は大きいので、話者の反対側に広い背景がある絵を選ぶ。
- 擬音は人物や動きの軌跡に重ねて置く。擬音が重なってもよい場所（背景、服の大きな黒）がある絵だと置きやすい。

### 2.4 アンカーと領域を測る

mangacli は素材の画素座標で書いたアンカーと領域を使って、しっぽの向きと自動配置を決める。絵を選んだら必ず測る。

| 書くもの | 使われ方 |
|---|---|
| `character: <id>` | `dialogue` の話者の画像として使う。しっぽは同じコマにある話者の画像へ向く |
| `anchors.mouth` | しっぽの向き先。自動配置は口を覆わない |
| `regions.face` | 自動配置で避ける。しっぽは向き先がこの顔の上にあれば、顔の手前で止まる |
| `regions.avoid` | 自動配置で避ける（2 人目の顔、見せたい手元など） |
| `anchors.<他のキャラクター>` | 1 枚に 2 人いる絵で、2 人目へしっぽを向ける（`tail: { to: <画像の id>.<キャラクター> }`） |
| `kind: background` | 話者のいない風景の絵 |

- 測り方: 絵に 10 % ごとの格子と画素座標を重ねた画像を作り、口と顔の外接矩形を読む。座標は **切り取る前の素材の画素** で書く（`focus` で切り取っても書き直さなくてよい）。
- 絵の端を切り落としたり大きさを変えたりしたら、座標もその分ずらす。
- 2 人いる絵では、`character` は主に話す方にし、もう 1 人は `anchors` と `regions.avoid` に書く。

### 2.5 絵を作り直すか、原稿を直すか

描いて見たときの問題は、軽い方から順に試す。

1. 吹き出しの `at` を動かす、改行を変える、`connect` でまとめる。
2. 画像の `focus`・`zoom` を変える。
3. 絵の一部を画像編集で直す（描かれた箱・文字・枠を消す）。
4. 絵を作り直す。動き（つまずく、よける、つかむ）が読めない、主役が大きすぎる、吹き出しの場所がない、の場合。

### 2.6 プロンプトのコツ

- **キャラクターの説明は毎回同じ文を付ける**。髪型・制服・持ち物まで固定の文にしておくと、コマが変わっても見た目がおおむね揃う。設定画を先に作っておくと、候補の照合に使える。
- **動きは体の向きと物の動きまで書く**。「つまずく」では立ったままになる。「頭から前へ倒れ込み、両腕を投げ出し、竹刀が手から飛ぶ」と書く。「竹刀が横をかすめる」は、竹刀が「絵の左の外から」来ると書かないと、本人が持っているように描かれる。
- **小さな人物は、風景を主役にして書く**。「小さく後ろ姿で」と書いても手前に大きく描かれがち。「無人の屋上、奥のフェンスに小さな人影が 1 つ」と書くと通る。
- **候補はプロンプトの言い回しで変える**。速いモデルはシードを変えても構図がほとんど変わらないことがある。同じ指示を 2〜3 通りに書き分けて候補を作る。
- **絵の文体はページを通して 1 つにする**。線の太さ・トーンの量・背景の描き込みが揃っていないと、写植を整えても 1 本の漫画に見えない。作り直したコマだけ文体が変わらないよう、文体の文は共通にしておく。
- **色が付いても白黒で確かめる**。`print-mono` で白黒にするので、夕日や頬の色は灰色のトーンになる。濃さが変わるので、白黒で描いた結果で判断する。

### 2.7 作業の流れ

1. 話とコマ割り（`layout`）を先に決め、コマごとの縦横比と、吹き出しを置く側を決める。
2. キャラクターの説明文と設定画を作る。
3. コマごとにプロンプトを書いて候補を作り、一覧にして選ぶ。
4. 選んだ絵の端を整え、アンカーと領域を測って `assets` に書く。
5. 原稿を書いて描き、ページ全体と拡大で確かめる。2.5 の順に直す。
6. 使ったプロンプトを残す（`art/prompts.json`）。作り直すときに同じ文体で描ける。

## 付録: この作例での生成の環境

- 生成には Sogni を使った（`tools/daemon.mjs`、`tools/enqueue.mjs`）。使い方は `README.md`。
- Relaxed ネットワークは SDK の `network: 'relaxed'` で使う。同じ `appId` の接続は 1 本までなので、デーモンは 1 つだけ動かす。
- 安定して使えたのは `qwen_image_2512_lightning`（1 枚 1 分ほど）と、編集用の `qwen_image_edit_2511_lightning_8bit`。
