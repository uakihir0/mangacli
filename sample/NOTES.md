# 作例づくりの記録 — 吹き出しのデザインと AI での絵の生成

作例「三十一戦目」を作り直したときに分かったことの記録。ライブラリで直したこと、原稿（`manga.yaml`）の書き方のコツ、Sogni で絵を生成するときのコツをまとめる。

## 1. 吹き出し・写植

### 1.1 直す前の問題

| 問題 | 原因 |
|---|---|
| しっぽが小さな突起にしか見えない | 話者の顔が本体のすぐ横にあると、しっぽを顔の手前で止めるため 2 mm ほどに縮んでいた |
| 別のキャラクターへのしっぽが手前の人物の顔で止まる | しっぽは向き先によらず、画像の `face` 領域（その画像の主役の顔）で止めていた |
| 枠からはみ出した吹き出しが、ページの余白まで飛び出す | 吹き出しの既定が `clip: none` で、外周の辺でも枠線の上に描いていた |
| 「──」が縦書きで横棒 2 本に分かれる | 罫線の `─` をダッシュとして扱わず、縦向きにもつながりもしなかった |
| 叫びの吹き出しのトゲが大きく不揃い | トゲの間隔・深さ・揺らぎが大きすぎた |

### 1.2 ライブラリで直したこと

| 項目 | 今の既定 | 変更前 |
|---|---|---|
| 吹き出しの `clip` | `auto`: コマの間の枠線には重ねて描き、枠の外周を越える場合は枠で切る。切る場合は本文を外周の辺から `max(2.5 bmm, 0.8em)` 内側へ寄せる | `none` |
| しっぽの最短の長さ | 4.5 bmm | 3.2 bmm |
| しっぽの `maxLength` | 本体の短辺の 60 %（4.5〜12 bmm） | 55 %（3.5〜10 bmm） |
| しっぽの付け根の幅 | 本体の短辺の 13 %（1.6〜2.8 bmm） | 10 %（1.1〜2.2 bmm） |
| しっぽを顔で止める条件 | 向き先がその顔の上（30 % 広げた範囲）にある場合だけ。曲がり（`curl`）の中心にも同じ条件 | 常に |
| ダッシュ | `─`・`━` も `―` として扱い、縦書きでは縦向きにして字送りいっぱいに伸ばす（縦用の字形がない書体でも） | `―`・`—` だけ |
| トゲ（`spike`） | 周長 ÷ 5 mm 本、深さ `[0.18, 0.28]`、`angleJitter: 0.2` | ÷ 6 mm、`[0.22, 0.34]`、`0.3` |

### 1.3 少年誌の写植の決まりごと（原稿を書くときの指針）

参考にした商業誌の見開きと、Sogni に描かせた吹き出し付きのページ（`refs/`）から読み取ったもの。

- **本文の大きさ**: B5 のページで 18 bQ 前後（`defaults.balloon.fontSize: 18bQ`）。小さいと吹き出しばかりが目立つ。強調するセリフだけ `fontScale` で大きくする。
- **改行**: 1 列は 4〜7 字。長いセリフは手で `\n` を入れて 2〜3 列にし、吹き出しを丸に近づける。「……」で始まるセリフは「……」だけを 1 列目に置くと間が出る（`"……\n来たか"`）。
- **置き場所**: コマの隅（読み始めの右上か、話者の頭の横）に寄せる。顔・口・手元を覆わない。外周の辺に寄せて **枠で切れる吹き出し** にすると、プロの写植らしくなる（`clip: auto` で自動）。
- **しっぽ**: 短く鋭く、話者の口へ向ける。しっぽが別の人物の頭を横切るなら、吹き出しを話者の側へ移す（しっぽを伸ばして解決しない）。
- **続くセリフ**: 同じ話者の続く 2 つの吹き出しは、少し重ねて輪郭を合成する（`connect: { to: <id>, style: overlap }`）。しっぽは先の吹き出しだけに付ける。
- **ルビ**: 名前などの読みにくい語に付ける（`<ruby=きりしま>霧島</ruby>`）。
- **叫び**: `as: shout`（トゲ）・`as: scream`（爆発）。話者の顔にかからないよう、コマの反対側に置いて枠で切る。
- **自動配置**: `at` を書かなければ顔を避けて置く。狭いコマでは `BALLOON_NO_SPACE` が出て髪や顔に重なることがあるので、絵を見て空の上などに `at` で置く。
- **ナレーション**: 断ち切りのコマでは安全領域の内側に置く（右端に寄せすぎると `TEXT_OUTSIDE_SAFE_AREA`）。

### 1.4 確認の手順

1. `npx mangacli render sample/manga.yaml -p print-mono` で描く（約 10 秒）。
2. ページ全体を見て、読み順・顔の隠れ・しっぽの向きを確認する。
3. 気になるところは拡大して見る（`sharp` で切り出して見る）。しっぽの長さ、枠で切れた吹き出しの残り、ダッシュのつながりは、縮小した絵では分からない。
4. 警告（`BALLOON_NO_SPACE`、`TEXT_OUTSIDE_SAFE_AREA`）は、その吹き出しを絵で確かめる。

## 2. Sogni での絵の生成

### 2.1 Relaxed で動かす

- REST の creative-agent workflow の API には Relaxed の指定が文書化されていない。SDK（`@sogni-ai/sogni-client`）を `network: 'relaxed'` で使う。
- **同じ `appId` の接続は 1 本まで**。2 本目をつなぐと 1 本目が切れ、生成中のジョブの結果を受け取れなくなる。そのため常駐のデーモン（`tools/daemon.mjs`）を 1 つだけ動かし、ジョブはファイル（`gen/queue/*.json`）で渡す。
- 並列数は 4（Unlimited プランの画像の同時実行数）。
- **使えるモデルは、ワーカーにそのモデルが読み込まれているかで決まる**。`qwen_image_2512_lightning` は 1 枚 50〜70 秒で安定。`qwen_image_2512_8bit`・`z_image_turbo_8bit`・`krea2_turbo_fp8_scaled` は待ち行列で何十分も始まらないか、100 % になっても結果が届かず、並列の枠をふさいだ。状況は `GET https://api.sogni.ai/v1/model-demand?network=relaxed` の `workersLoaded`・`jobsQueued` で分かる。
- 編集モデル `qwen_image_edit_2511_lightning_8bit`（`contextImages` に元の絵）も Relaxed で動く。1 枚 7 分ほど。
- 完了のイベントが届かないことがあるので、デーモンはジョブの状態も定期的に見て結果の URL を取りに行く。

### 2.2 プロンプトのコツ

- **「empty space」と書かない**。「empty space on the right」と書くと、右に白い箱（枠や吹き出し）を描いてしまう。代わりに「右側はその背景（空・グラデーション）が端まで続く」と、そこに描くものを書く。
- **枠を描かせない**。「A single full-bleed illustration that fills the whole canvas edge to edge. No borders, no frames, no white boxes, no inset panels.」を文体に入れる（`art/prompts.json` の `styleFullBleed`）。それでも端に細い枠線が出ることがあるので、20〜36 px 切り落とす。
- **候補の差は小さい**。lightning は同じプロンプトだとシードを変えても構図がほとんど変わらない。候補を増やすなら `--n` を増やすより、言い回しを変えたプロンプトを複数作る（`p1-1a`・`p1-1b`・`p1-1c` のように）。
- **小さな人物は言い方を変える**。「小さく後ろ姿」と書いても大きな人物を手前に描きがち。「無人の屋上。奥のフェンスに小さな人影が 1 つ」と、主役を風景の方に置き換えると通る。
- **動きは具体的に**。「つまずく」では立ったままになる。「頭から前へ倒れ込み、両腕を投げ出し、竹刀が手から飛ぶ」のように、体の向きと物の動きを書く。「竹刀が横をかすめる」は、竹刀が「絵の左の外から」来ることまで書かないと、本人が持っているように描かれる。
- **キャラクターの説明は毎回同じ文を付ける**（`spec.hayato`・`spec.mio`）。髪型・制服・持ち物まで書くと、コマが変わっても見た目がおおむね揃う。設定画（`chars/`）を先に作っておくと照合に使える。
- **竹刀は難しい**。「shinai」と書いても刀の柄に竹の刀身を付けた形になる。作例ではそれで統一している。
- **色が付くことがある**（夕日・頬・目が赤い）。`print-mono` で白黒にするので問題はないが、トーンの濃さが変わる。

### 2.3 絵を選んで原稿に入れる

1. 候補を一覧にして比べる（縮小して並べた 1 枚の画像を作る）。
2. 選んだ絵に 10 % ごとの格子と座標を重ねて、口（`anchors.mouth`）と顔（`regions.face`）の画素座標を読む。別のキャラクターのアンカー（`anchors.hayato` など）も同じように置く。
3. 絵の中に描かれてしまった枠や箱は、編集モデルで消す（「左上の白い箱を消し、周りと同じ空で埋める。ほかは変えない」）。
4. 使ったプロンプトは `art/prompts.json` に残す。

### 2.4 コマンド

```bash
cd sample/tools && npm install && cd ../..
node sample/tools/daemon.mjs &                              # 常駐（1 つだけ）
node sample/tools/enqueue.mjs sample/art/prompts.json --n 2  # 足りない絵を積む
tail -f sample/gen/log.txt                                  # 進み具合
```
